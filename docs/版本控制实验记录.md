## 5. 冲突处理

本次实际开发未出现 Git 冲突。各模块目录相互独立，根 `pom.xml`、README 等公共文件在合并前由 `feature/collaboration` 统一提交，因此没有产生冲突。

如果后续出现冲突，按以下流程处理：

```bash
git switch dev
git merge --no-ff feature/<module>
# 打开冲突文件，保留双方必要逻辑
git add <resolved-file>
git commit
mvn test
```

原则：

- 不直接选择“ours”或“theirs”覆盖业务代码；
- 解决后必须重新运行全部测试；
- 共享分支不使用 `git push --force`。

远程配置：

```bash
git remote add origin git@github.com:leisure113/sofeware.git
```

SSH 连接验证：

```text
Hi leisure113! You've successfully authenticated, but GitHub does not provide shell access.
```

`main` 原有内容为 lab01 提交 `89feb52`；本次课程设计经确认覆盖 `main`，使用本地 `master` 推送为远程 `main`。`dev` 和各 feature 分支一并推送，便于查看分支和合并记录。

推送命令：

```bash
git push --force-with-lease=main:89feb52 origin master:main
git push -u origin dev
git push origin feature/team-module feature/user-module feature/content-module feature/governance-module feature/collaboration
git push --tags
```

> 注：当前 DSH 沙箱内 Git 调用 SSH 会出现 named pipe 限制，实际推送在允许 full-access 的终端或普通终端执行。
